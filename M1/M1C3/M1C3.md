## 🎬 M1C3L2 — Définir le Vibe Coding *(3 min)*

<aside>
🎯

**Angle** : démystifier d'entrée. On répond à « c'est quoi, concrètement ? » avec une définition simple, puis on montre le changement de posture. Pas de jargon, beaucoup de concret.

</aside>

<aside>
🎬

**Ce qu'on peut dire en intro**

*« Cette leçon pose la définition du Vibe Coding. On va voir ce que le terme veut dire concrètement, comment se répartissent les rôles entre l'humain et l'IA, et ce que le Vibe Coding n'est pas. À la fin, on saura le définir en une phrase et expliquer en quoi il change la façon de créer un logiciel. »*

</aside>

### 🔑 Les points clés à détailler

- **La définition** : on décrit son intention en langage naturel, l'IA génère le code. On dialogue, l'IA exécute.
- **L'idée derrière le mot** : se laisser porter par le « flow ». On guide, on ne tape plus chaque ligne.
- **Le changement de posture** : on passe d'exécutant à chef d'orchestre. La question n'est plus « comment l'écrire ? » mais « qu'est-ce qu'on veut obtenir ? ».
- **Qui fait quoi** : l'humain garde l'intention, les choix et la validation ; l'IA produit le code.
- **Ce que ce n'est pas** : ni magie, ni « l'IA fait tout toute seule ». Sans intention claire, pas de bon résultat.

## 🎬 M1C3L3 — Histoire et développement récent *(~10 min)*

<aside>
🎯

**Angle** : raconter l'histoire comme une fresque. Comment on est passé, en ~5 ans, de « écrire chaque ligne à la main » à « décrire et laisser l'IA coder ». Leçon exhaustive et vivante qui légitime le Vibe Coding comme aboutissement logique d'une évolution, pas comme un effet de mode. Factuel, daté, sans sensationnalisme.

</aside>

<aside>
🎬

**Ce qu'on peut dire en intro**

*« Cette leçon retrace l'histoire du Vibe Coding, des premiers outils d'IA pour le code jusqu'à aujourd'hui. On va suivre la chronologie : les briques techniques, les premiers copilotes en 2021, ChatGPT, le saut de qualité des modèles, le moment où Andrej Karpathy a nommé le terme début 2025, puis l'arrivée des agents. Objectif : comprendre ce qui a rendu le Vibe Coding possible, et pourquoi maintenant. »*

</aside>

### 🔑 Les points clés à détailler

- **Le point de départ** : longtemps, coder = écrire chaque ligne soi-même, chercher sur Stack Overflow, des années d'apprentissage avant de produire quoi que ce soit.
- **La brique de base (2017)** : l'architecture Transformer (« Attention is all you need ») permet aux modèles de comprendre et générer du langage — donc aussi du code.
- **2021, les premiers copilotes** : OpenAI Codex, puis GitHub Copilot. L'autocomplétion intelligente arrive dans l'éditeur. L'IA devient un « copilote ».
- **Fin 2022, ChatGPT démocratise** : tout le monde peut générer du code en conversation. C'est la phase « copier-coller depuis le chat ».
- **2023-2024, l'IA entre dans l'IDE** : Cursor, Copilot Chat. La boucle « décrire → générer → tester » se fait dans un seul endroit.
- **Le saut de qualité des modèles** : avec Claude 3.5 Sonnet (fin 2024), le code généré devient fiable au point de « faire confiance ». C'est le vrai déclencheur.
- **3 février 2025, le mot naît** : Andrej Karpathy (cofondateur d'OpenAI, ex-directeur IA de Tesla) poste le terme « vibe coding ». Sa formule : *se laisser porter par les vibes… et oublier que le code existe*. Possible, dit-il, parce que les modèles (ex. Cursor Composer + Sonnet) sont « devenus trop bons ». Il code même à la voix.
- **2025, l'année des agents** : Claude Code (aperçu en février, version complète en mai), l'agent Codex, puis les IDE agentiques — Windsurf, et Google Antigravity en novembre. L'IA passe d'assistant à agent qui planifie, code et teste.
- **Un phénomène déjà culturel** : le terme entre chez Merriam-Webster (mars 2025) et devient « mot de l'année » du Collins Dictionary 2025.
- **Pourquoi maintenant ?** La convergence de quatre choses : des modèles fiables + de grandes fenêtres de contexte + des capacités agentiques (accès au terminal, aux outils) + des interfaces accessibles (web, voix).
- **Et après ?** Le terme évolue déjà : dès 2026 on parle d'« ingénierie agentique » pour le travail de production, distinct du Vibe Coding « prototype ». *(pont vers la suite de la formation)*

## 🎬 M1C3L4 — Distinguer Vibe Coding, no-code et développement classique *(5 min)*

<aside>
🎯

**Angle** : la leçon la plus structurante du chapitre. On clarifie les trois façons de créer une application aujourd'hui, sans en opposer une seule — chacune a sa place. La slide comparative fait le gros du travail. Découpage plus dense.

</aside>

<aside>
🎬

**Ce qu'on peut dire en intro**

*« Cette leçon compare les trois façons de créer une application aujourd'hui : le développement classique, le no-code et le Vibe Coding. On va voir comment chacune fonctionne, ses forces et ses limites, puis quand choisir l'une plutôt qu'une autre. Objectif : savoir situer le Vibe Coding sans opposer les approches. »*

</aside>

### 🔑 Les points clés à détailler

- **Le développement classique** : écrire le code à la main. Contrôle et flexibilité totaux. Le prix ? De l'expertise et du temps.
- **Le no-code** : assembler visuellement par blocs (glisser-déposer). Rapide, sans coder. La limite ? On reste dans le cadre de l'outil, difficile d'en sortir, et on dépend de la plateforme.
- **Le Vibe Coding** : décrire à l'IA, qui génère du vrai code. La flexibilité proche du dev classique, l'accessibilité proche du no-code. Le prix ? Savoir guider, valider, et comprendre les bases.
- **Le comparatif sur 5 critères** : compétence requise, vitesse de démarrage, flexibilité, contrôle et propriété du code, limites.
- **Quel choix, quand ?** Prototype jetable, MVP, app sur-mesure, outil interne, projet destiné à durer.
- **La nuance à garder** : ce ne sont pas des cases étanches. On combine souvent — par exemple, le no-code pour tester une idée, le Vibe Coding pour l'industrialiser.

### 🔑 Les points clés à détailler

- **Les familles d'outils** : les assistants intégrés à l'éditeur, les IDE agentiques (forks de VS Code), les agents en terminal (CLI), et les plateformes web tout-en-un.
- **GitHub Copilot** : le pionnier (2021). Assistant intégré à l'éditeur, autocomplétion + chat. Public : développeurs.
- **Cursor** : l'IDE de référence (fork de VS Code), célèbre pour son Composer. Très adopté par les pros du Vibe Coding.

- **Comment choisir** : selon le besoin (prototype vs app durable), la prise en main, le budget — et surtout le modèle sous-jacent, qui fait souvent la plus grande différence.
- **Le point clé** : les outils changent, la logique reste. Inutile de tous les apprendre.
