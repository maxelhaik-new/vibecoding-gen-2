# Brand Voice — Règles de Rédaction Pédagogique

---

## 1. RÈGLES DE SUBSTANCE — Priorité absolue

> Ces règles s'appliquent **avant toute règle de forme**. Un texte formellement correct mais creux est un échec.

**Chaque phrase doit apporter une information que le titre seul ne donne pas.**
Si on peut inférer le contenu d'un bloc depuis son titre, la phrase est à réécrire.

**Toute affirmation générale doit être ancrée dans un fait précis.**
Un chiffre, une date, un cas réel, une source. Pas de généralisation flottante.
- ❌ *"Le Vibe Coding change le rapport au logiciel."*
- ✅ *"63 % des utilisateurs d'outils de Vibe Coding ne sont pas développeurs. (Replit, 2025)"*

**Interdiction absolue des formules méta sur l'IA.** Ces phrases ne disent rien de concret :
- ❌ *"L'humain pilote, l'IA exécute."*
- ❌ *"L'IA augmente les capacités humaines."*
- ❌ *"Travailler avec l'IA change tout."*
- ❌ *"L'IA comme copilote."*
→ Les remplacer par ce que l'outil fait **concrètement** dans le cas présenté.

**Une bulle ≠ un résumé du texte principal.**
La `Bulle` / `Texte Bulle` doit apporter un angle différent, un principe actionnable, ou une info supplémentaire — jamais reformuler ce qui vient d'être dit.

**Aucun exemple ne peut apparaître deux fois dans la même leçon.**
Si un cas est développé dans une slide FOCUS OUTIL, il ne peut pas être repris dans la slide suivante.

---

## 2. TON DE VOIX

### A. Fluidité conversationnelle
Le contenu doit sembler écrit par un formateur expert, direct et vivant.
- **Questions de transition courtes** : *« Le problème ? »*, *« Ça s'applique quand ? »*, *« Comment faire ? »*
- **Expressions de complicité** : *« En réalité, ... »*, *« À nous de jouer ! »*
- **Ponctuation vivante** : points d'exclamation ponctuels, tirets, pas de virgules en cascade.

### B. Interdiction de l'adresse directe
- **Interdit** : *"vous"*, *"tu"*, verbes conjugués à ces personnes.
- **Obligatoire** : pronom *"on"* ou infinitif.
  - ❌ *"Vous configurez le projet."* → ✅ *"On configure le projet."*
  - ❌ *"Choisissez un modèle."* → ✅ *"Choisir un modèle adapté."*
- **Exception** : les conseils derrière flèche (`→`) utilisent l'impératif 2e personne du pluriel.

### C. Concision chirurgicale
- Une idée par phrase. **Maximum 15 mots** par phrase dans les blocs courants.
- Pas d'introduction scolaire (*"Dans cette leçon, nous allons voir..."*).

## 3. EXPRESSIONS RECOMMANDÉES

| Expression | Usage | Exemple |
| :--- | :--- | :--- |
| **On** | Pronom universel, remplace "vous/tu" | *« On obtient le résultat en 3 étapes. »* |
| **Le problème ?** | Introduire un point de douleur ou un défi | *« Le problème ? Cette méthode est lente. »* |
| **En réalité, ...** | Casser une idée reçue, nuancer | *« En réalité, l'outil s'adapte très bien. »* |
| **En bref, ...** | Conclusion rapide, résumé dense | *« En bref, la méthode économise 40 % de temps. »* |
| **Ça s'applique quand ?** | Définir le contexte d'usage d'une méthode | *« Ça s'applique quand ? Idéal pour le prototypage rapide. »* |
| **À nous de jouer !** | Transition vers une démo ou un exercice pratique | *« À nous de jouer ! Créons le premier prompt. »* |
| **→ [Impératif 2e pl.]** | Conseil derrière flèche uniquement | *« → Gardez le brief accessible pendant toute la session. »* |

## 4. BLACKLIST — Tournures interdites

| Interdit | Remplacement | Exemple corrigé |
| :--- | :--- | :--- |
| **Vous / Tu** (hors flèche) | **On** / Infinitif | *« On configure le serveur. »* |
| **Il est crucial / essentiel de...** | **Règle :** / Infinitif direct | *« Règle : valider le schéma avant envoi. »* |
| **L'humain pilote, l'IA exécute** | Décrire l'action concrète dans le contexte | *« Cursor génère les tests, on valide avant merge. »* |
| **L'IA augmente / démultiplie** | Chiffrer le gain ou nommer l'action précise | *« Le script réduit le temps de rendu de 50 %. »* |
| **Révolutionnaire / Puissant / Incroyable** | Gains réels et chiffrés | *« Réduit le temps de déploiement de 3 h à 8 min. »* |
| **Optimiser / Maximiser** | **Améliorer / Simplifier / Ajuster** | *« Améliorer les performances du script. »* |
| **Faciliter** | **Permettre de / Rendre possible / Aider à** | *« Rendre le déploiement plus fluide. »* |
| **Au cœur de... / Le paysage de...** | Nommer directement le concept ou le secteur | *« L'écosystème du Vibe Coding en 2026. »* |
| **En conclusion / En somme** | **En bref** | *« En bref : Git versionne, Vercel déploie. »* |
| **Permettre de garantir** | **Garantir / Assurer** | *« Assurer la sécurité du code. »* |
| **Tout au long de ce cours...** | Aller directement au concept | *« Cursor interprète le contexte à partir de... »* |
| **Explorez / Apprenez / Découvrez** (hors flèche) | Infinitifs | *« Explorer les modes de prompt. »* |
| **L'IA comme copilote / assistant** | Nommer l'outil et son action précise | *« Claude génère la structure, on affine. »* |

## 5. STRUCTURE GRAMMATICALE PAR CHAMP

### `Titre` (slide)
Format nominal court ou question directe. Pas de verbe conjugué.
- ✅ *"Le cas du New York Times"*, *"Ça s'applique quand ?"*, *"Ses principales limites"*

### `Intro`
Une phrase factuelle posant le cadre. Affirmative ou interrogative. Peut prendre la forme **Question ? Réponse.** sur une seule ligne.
- ✅ *"Quand utiliser Few-shots ? Les cas d'usage idéaux"*
- ✅ *"Midjourney, malgré son développement rapide, se bute encore à certaines limites techniques."*
- ✅ *"DALL-E s'est imposé indirectement comme une référence mondiale grâce à l'adoption massive de ChatGPT."*

### `Titre X` (blocs multi : 3 BLOCS, 4 BLOCS, etc.)
**EN MAJUSCULES**. Court, nominal. Pas de verbe.
- ✅ *"PRODUCTION EN SÉRIE"*, *"CRITÈRES DE SÉLECTION"*, *"SANTÉ"*
- ❌ *"La production en série"* (pas de majuscules) *"Gérer la production"* (pas de verbe)

### `Texte X` (blocs multi)
Commence par une description nominale ou un infinitif. Pas de sujet introductif. Peut se terminer par un contexte ou une nuance courte.
- ✅ *"Posts réseaux sociaux, fiches produits, descriptions, emails récurrents avec style identique"*
- ✅ *"Maintenir un personnage identique sur plusieurs créations reste un défi malgré les seeds"*
- ✅ *"Garder le même ton sur plusieurs contenus sans tout ré-expliquer à chaque fois"*

### `Titre X` (CHECKLIST / OBJECTIF CHAP)
Infinitif actif. Pas de numérotation (déjà intégrée dans Figma).
- ✅ *"Définir le sujet et le style de l'image"*
- ✅ *"Comprendre le principe agentique appliqué au code"*

### `Bulle` / `Texte Bulle`
Commencer par un marqueur fort (`EN BREF`, `TRAVAILLONS ÉTAPE PAR ÉTAPE !`). Apporter une info ou un angle **absent du texte principal**. Peut se terminer par une question ouverte.
- ✅ *"EN BREF : Few-shot excelle pour reproduire un pattern identifiable avec 2-3 exemples au lieu de longues instructions"*
- ✅ *"EN BREF : Même si la formation est centrée sur Midjourney, on verra comment créer des images avec GPT Image !"*
- ✅ *"Le procès est encore en cours, mais il pose une question fondamentale : un modèle d'IA peut-il apprendre sur des contenus protégés puis les concurrencer ?"*

### `QUELQUES CONSEILS`
Flèche `→` + impératif 2e personne du pluriel.
- ✅ *"→ Gardez le brief accessible pendant toute la session."*
- ✅ *"→ Nommez clairement chaque conversation dans Cursor."*

### Template `VIBECODING - INTRO` — Règles spécifiques et de formulation

Ce template comporte 8 champs dans le JSON (`Titre`, `Intro`, `Titre 1/2/3`, `Texte 1/2/3`) avec chacun sa logique propre.

**`Titre`** (Titre principal) : Peut être nominal, une question directe, ou une exclamation dynamique.
- ✅ *"Introduction"*, *"Introduction à l'IA Act"* (neutre)
- ✅ *"De quoi parlons-nous ?"*, *"Prenons les commandes !"* (dynamique)
- ✅ *"La notion d'éthique"*, *"Définir la créativité"* (thématique)

**`Intro`** (Texte d'accroche, 1-2 phrases) : Pose le cadre de la leçon. Il doit impérativement se terminer par une invitation à démarrer (ex : avec un verbe de mouvement comme *"Voyons..."*, *"Découvrons..."*, *"Faisons le point..."*, *"Faisons le tour..."*).
Structures typées :
- Constat factuel + invitation : *"Midjourney s'est imposé comme leader mondial depuis 2022. Voyons pourquoi."*
- Affirmation + retournement + invitation : *"L'IA peut sembler impartiale... mais elle hérite en réalité des biais humains. Voyons comment les limiter !"*
- Question rhétorique intégrée + invitation : *"On pourrait croire que les données individuelles ne sont pas conservées. Qu'en est-il réellement ? Faisons le point."*

**`Titre 1`, `Titre 2`, `Titre 3`** (Titre de bloc, court) : 2-5 mots, nominal ou question courte.
- ✅ *"Quelques avantages"*, *"L'outil face à la concurrence"*, *"L'IA dans tout ça ?"*

**`Texte 1`, `Texte 2`, `Texte 3`** (Sous-titre de bloc, 1 phrase) : Annonce ce qui va être vu dans la section correspondante de la leçon. Chaque texte doit **strictement débuter par** l'une des formulations suivantes :
- `Voyons...` (ex : *"Voyons les limites graphiques de l'outil."*)
- `Zoom sur...` (ex : *"Zoom sur quelques astuces pour y pallier."*)
- `Focus sur...` (ex : *"Focus sur le processus de création."*)
- `Découvrons...` (ex : *"Découvrons comment configurer son espace."*)
- `Apprenons à...` (ex : *"Apprenons à repérer les usages à risques."*)

⚠️ **Règle de curiosité (Non-Spoil)** : Ces textes ne doivent **jamais lister ou nommer précisément** les exemples ou réponses qui seront révélés dans les slides suivantes (ex: ne pas écrire *"Voyons trois projets réels — app médicale, curation de données, micro-SaaS"* mais plutôt *"Voyons trois projets réels lancés par des non-développeurs et qui se sont démarqués par leur originalité."*). Le texte doit introduire le sujet général et ouvrir comme une question ou susciter l'intérêt sans donner les détails à l'avance.
*Note pour les agents : Si une slide d'introduction existe déjà dans Figma pour la leçon cible, elle doit être totalement ignorée lors de la lecture du contexte afin de ne pas reproduire un mauvais brouillon existant.*

### Templates à Haute Densité (`VIBECODING - 6 BLOCS` / `5 BLOCS`)
*   **Quand l'utiliser** : Idéal pour les slides de vulgarisation de notions multiples, les listes d'outils, les paramètres précis ou les biais d'apprentissage.
*   **Règles de remplissage** :
    *   Chaque bloc doit être extrêmement concis.
    *   Associer systématiquement une icône MDI spécifique et pertinente pour chaque bloc (voir `icon_mapping.md`).

### Templates de Comparaison & Process (`VIBECODING - COMPARAISON` / `PROCESS`)
*   **Quand l'utiliser** : `VIBECODING - COMPARAISON` Parfait pour comparer des outils, des methodes ou des concepts. `PROCESS` Parfait pour expliquer une suite chronologique ou un processus.
*   **Règles de remplissage** :
    *   Pour `VIBECODING - COMPARAISON`, structurer les arguments en opposition face-à-face directe.
    *   Pour `PROCESS`, formuler les étapes par des verbes à l'infinitif actif.

### Templates d'Illustration (`VIBECODING - FOCUS OUTIL` / `VIBECODING - 3 BLOCS - PHOTO`)
*   **Quand l'utiliser** : Slides nécessitant un support visuel fort (capture d'écran, maquette Figma, illustration artistique).
*   **Règles de remplissage** :
    *   Garder les textes courts pour ne pas surcharger la slide.
    *   Remplir le champ `Source` avec le crédit ou le titre de l'image (ex : *« Image : Wemodo (Capture d'écran) »*).

### Template Acronyme (`VIBECODING - ACRONYME`)
*   **Quand l'utiliser** : Exclusivement pour détailler un acronyme (de 3 à 5 lettres max).
*   **Règles de remplissage** :
    *   Les lettres de l'acronyme doivent être placées dans les champs `Lettre 1` à `Lettre 5`.
    *   Les noms complets (ou significations de la lettre) doivent être placées dans les champs `Violet 1` à `Violet 5`.
    *   Les descriptions détaillées doivent être placées dans les champs `Texte 1` à `Texte 5`.
    *   Si l'acronyme comporte moins de 5 lettres, laisser les blocs restants vides.

### Template Définition (`VIBECODING - DEFINITION`)
*   **Quand l'utiliser** : Pour définir formellement un terme technique ou un mot informatique.
*   **Règles de remplissage** :
    *   Le mot à définir doit être placé dans le champ `Mot`.
    *   L'explication ou la définition détaillée va dans le champ `Definition`.
    *   Le champ `Bulle` sert à ajouter une remarque, un exemple court ou un point d'attention.

### Template Concept (`VIBECODING - CONCEPT`)
*   **Quand l'utiliser** : Pour introduire une idée clé, un concept général, ou une théorie non technique.
*   **Règles de remplissage** :
    *   Le titre du concept va dans le champ `Titre`.
    *   La phrase de résumé ou d'impact (gros caractères) va dans le champ `Intro`.
    *   Le développement explicatif (discours fluide en 3-4 phrases) va dans le champ `Texte 1`.

### Template Vide Sur-Mesure (`VIBECODING - VIDE`)
*   **Quand l'utiliser** : Pour dessiner des schémas personnalisés, des diagrammes, ou des mises en page libres.
*   **Règles de remplissage** :
    *   Remplir le `Titre` et l'`Intro`.
    *   Les nouveaux éléments visuels (blocs de texte supplémentaires, rectangles d'arrière-plan, icônes) doivent être générés en spécifiant des actions de type `create_node` dans le JSON de correction en ciblant la slide parente comme conteneur.

## 6. GESTION DES CONTRAINTES DE LONGUEUR

Avant d'écrire, lire les contraintes dans `templates.json` pour chaque champ :

- **Logique 1 — Limite Min/Max stricte** : Le texte rédigé doit avoir une longueur en caractères strictement comprise entre `min_lenght` et `max_lenght` inclus. Tout dépassement de la valeur maximale est interdit.
- **Logique 2 — Longueur cible avec marge** (champs avec `target_lenght`) : Viser précisément `target_lenght` avec une tolérance de **-10 % à +10 %** (min = `0.90 × target_lenght`, max = `1.10 × target_lenght`). Ne jamais écrire un texte trop court. Ne jamais rembourrer artificiellement un texte pour atteindre la cible.

## 7. CHECKLIST DE RELECTURE

À appliquer slide par slide avant de finaliser la leçon :

- [ ] Chaque phrase apporte une info que le titre seul ne donnait pas
- [ ] Au moins un fait concret (chiffre, cas, date, source) par slide substantielle
- [ ] Aucune formule de la blacklist n'est présente
- [ ] La bulle apporte un angle différent du texte principal
- [ ] Aucun exemple identique dans deux slides de la même leçon
- [ ] Aucune adresse directe (vous/tu) hors flèche conseil
- [ ] Aucun backtick (`) parasite dans les valeurs texte

## 8. FEW-SHOT EXAMPLES — Slides de référence

> ⚠️ **Ces exemples sont la référence stylistique absolue. En cas de doute sur le ton ou la densité d'information, s'y reporter avant d'écrire.**

> Note : Ces exemples viennent d'une formation précédente. Les noms de templates diffèrent mais **le ton, les formulations et la densité d'information sont la référence à atteindre**.

---

### Exemple 1 — USE CASE

**Titre** : `Le cas du New York Times`

**Titre de section** : `NEW YORK TIMES VS OPENAI`

**Sous-titre** : `Qui possède les contenus qui nourrissent l'IA ?`

**Texte principal** : `Le New York Times a poursuivi OpenAI et Microsoft en justice pour une raison simple mais explosive : OpenAI a utilisé des millions d'articles du journal (enquêtes, analyses, archives) pour entraîner ChatGPT, sans demander l'autorisation ni payer de licence. Le problème ? Maintenant, ChatGPT peut générer des résumés d'actualités ou des textes similaires aux articles originaux, sans renvoyer vers le NYT et sans partager de revenus.`

**Bulle** : `Le procès est encore en cours, mais il pose une question fondamentale : un modèle d'IA peut-il apprendre sur des contenus protégés puis les concurrencer ? Faut-il toujours attribuer les sources du contenu IA ?`

> 🔍 Ce qui fonctionne : le fait réel précis dȲs la première phrase, "Le problème ?" comme pivot narratif, bulle qui ouvre sur une question ouverte au lieu de résumer.

---

### Exemple 2 — MULTI-BLOCS (4 ou 5 blocs)

**Titre** : `Ses principales limites graphiques`

**Intro** : `Midjourney, malgré son développement rapide, se bute encore à certaines limites techniques comme la plupart des IA génératives d'images.`

**Titre 1** : `TEXTE DANS LES IMAGES ENCORE DIFFICILE`
**Texte 1** : `Génération de lettres, typographies, logos : on obtient souvent des résultats incohérents nécessitant retouches externes`

**Titre 2** : `MAINS ET ANATOMIE COMPLEXE IMPÉCISES`
**Texte 2** : `Doigts déformés, positions anatomiques impossibles : on doit multiplier les générations pour obtenir un résultat correct`

**Titre 3** : `COHÉRENCE ENTRE LES IMAGES LIMITÉE`
**Texte 3** : `Maintenir un personnage identique sur plusieurs créations reste un défi malgré les seeds et style references`

**Titre 4** : `CONTRÔLE PRÉCIS DES DÉTAILS DIFFICILE`
**Texte 4** : `Placer des éléments spécifiques exactement où on veut : le prompt seul ne suffit pas toujours pour un contrôle pixel-parfait`

> 🔍 Ce qui fonctionne : Titres EN MAJUSCULES, chaque Texte X commence par une liste ou un constat factuel sans sujet introductif, deux-points comme pivot entre cause et conséquence.

---

### Exemple 3 — CHIFFRES

**Titre** : `GPT Image en quelques chiffres`

**Intro** : `DALL-E s'est imposé indirectement comme une référence mondiale de l'image générative grâce à l'adoption massive de ChatGPT. Le modèle GPT Image lui succède officiellement depuis la fin 2025.`

**Chiffre 1** : `100+` | **Titre 1** : `M D'UTILISATEURS` | **Texte 1** : `Utilisateurs actifs qui créent quotidiennement sur la plateforme OpenAI.`

**Chiffre 2** : `1.5` | **Titre 2** : `GPT IMAGE` | **Texte 2** : `Dernier modèle actuel avec une génération instantanée et une précision sémantique accrue.`

**Chiffre 3** : `25` | **Titre 3** : `SECONDES` | **Texte 3** : `Vitesse moyenne pour obtenir un résultat exploitable en HD (1500x2000px).`

> 🔍 Ce qui fonctionne : l'Intro est factuelle et donne le contexte historique, chaque Texte X est une phrase courte qui complète le chiffre sans répéter le Titre.

---

### Exemple 4 — CONCEPT / INTRO

**Titre** : `La fonction describe`

**Intro** : `La fonction "describe" permet de connaître le vocabulaire de Midjourney en analysant des images existantes.`

**Bloc gauche — Titre** : `Qu'est-ce que describe ?`
**Bloc gauche — Texte** : `Une fonction qui analyse une image uploadée et génère 4 prompts qui pourraient recréer une image similaire. C'est comme avoir accès à la "pensée" de Midjourney.`

**Bloc droit — Titre** : `Comment l'utiliser ?`
**Bloc droit — Texte** : `1. Glissez une image dans la section "Describe" du panneau image. 2. Analysez les 4 prompts générés`

**Conseils** :
`→ D'ajouter de nouveaux termes techniques à notre vocabulaire pour les ré-utiliser`
`→ De comprendre comment Midjourney "voit" et décrit les images`

> 🔍 Ce qui fonctionne : l'Intro est une phrase définition dense, la métaphore "C'est comme avoir accès à la pensée de..." est concrète et imagiste, les → sont des infinitifs transformés en complément du titre de section.

---

### Exemple 5 — FIN / EN RÉSUMÉ

**Titre** : `En résumé`

**Texte principal** : `GPT Image, le modèle de création visuelle intégré à ChatGPT, ne s'impose pas comme l'option la plus technique et précise, mais permet d'obtenir des images IA de bonne qualité, avec peu d'erreur dans l'intégration de textes, tout en restant dans l'outil et gardant le contexte de nos projets. On privilégiera cette option pour le prototypage rapide, et il peut même être un bon complément à Midjourney pour l'expérimentation.`

**Bulle EN BREF** : `Même si la formation est centrée sur Midjourney pour son aspect professionnel et sa qualité de rendu, on verra dans les prochaines leçons comment créer des images avec GPT Image !`

> 🔍 Ce qui fonctionne : bilan objectif (positif + nuances réelles), pas de superlatif, "On privilégiera" comme recommandation naturelle, bulle EN BREF qui ouvre sur la suite sans résumer ce qui vient d'être dit.

### Exemple 6 — INTRO (pattern : affirmation + retournement)

**Titre principal** : `De quoi parlons-nous ?`

**Accroche** : `L'IA peut sembler impartiale car ses décisions reposent sur des calculs mathématiques... mais elle hérite en réalité des biais humains présents dans ses données d'entraînement.`

**Titre bloc 1** : `Le mythe de l'impartialité`
**Sous-titre bloc 1** : `Les algorithmes apprennent à partir de données créées par des humains, reproduisant ainsi nos préjugés et stéréotypes dans leurs résultats.`

**Titre bloc 2** : `Discrimination algorithmique`
**Sous-titre bloc 2** : `Lorsque ces biais touchent des variables sensibles (genre, origine, âge...), ils portent atteinte aux droits fondamentaux et créent des injustices.`

> 🔍 Ce qui fonctionne : l’accroche utilise le retournement *"... mais en réalité"* pour créer une tension narrative immédiate. Les sous-titres de blocs sont des phrases affirmatives complètes, pas des "Voyons..." — preuve que la forme invitante n'est pas obligatoire.

---

### Exemple 7 — INTRO (pattern : constat factuel + questions directes)

**Titre principal** : `Introduction`

**Accroche** : `Les erreurs de texte et les artefacts visuels sont les deux limites graphiques les plus courantes de Midjourney, car elles compromettent la qualité professionnelle de nos créations. Voyons les types de défauts courants avec quelques exemples.`

**Titre bloc 1** : `Les textes dans les images`
**Sous-titre bloc 1** : `Quelles sont les erreurs liées aux textes dans les images les plus probables ?`

**Titre bloc 2** : `Détecter les artefacts visuels`
**Sous-titre bloc 2** : `Comment identifier les défauts anatomiques, les textures impossibles et les incohérences visuelles ?`

> 🔍 Ce qui fonctionne : l’accroche pose le diagnostic précis dès la première phrase (deux limites nommées, raison donnée). Les sous-titres sont des questions directes — alternative valide aux formes *"Voyons..."*.

### Exemple 8 — INTRO (pattern : continuité depuis la leçon précédente)

**Titre principal** : `Comment réduire un biais de l'IA ?`

**Accroche** : `On l'a vu, l'IA hérite des biais humains présents dans ses données d'entraînement et peut être la source de discriminations involontaires. Voyons comment les limiter !`

**Titre bloc 1** : `Les bonnes pratiques`
**Sous-titre bloc 1** : `Même si l'on ne peut pas agir sur les données d'entraînement, quelques points d'attention permettent de limiter les biais à l'usage.`

**Titre bloc 2** : `Réduire un biais manuellement`
**Sous-titre bloc 2** : `Voyons quelques techniques pour "forcer" un modèle IA à réduire et même effacer un biais que l'on a identifié dans le contenu !`

> 🔍 Ce qui fonctionne : *"On l'a vu"* crée la continuité avec la leçon précédente sans intro scolaire. Le titre principal est une question directe, plus engageant que *"Introduction"*. Les sous-titres alternent affirmation et *"Voyons..."*.

### Exemple 9 — INTRO (pattern : contexte factuel + question rhétorique)

**Titre principal** : `La protection de données`
